# TG-Auto-Publisher

بازنشر خودکار پست‌های کانال‌های تلگرام با یک حساب کاربری، با GitHub Actions.
هر پست به‌صورت یک پست جدید (بدون هدر Forward) در مقصد منتشر می‌شود.

## امکانات

- متن، عکس، ویدئو، موسیقی، ویس و فایل، با حفظ قالب‌بندی (بولد، ایتالیک، لینک)
- آلبوم کامل (چند عکس/ویدئو در یک پست)
- ارسال مجدد مدیا بدون دانلود (سریع)؛ در صورت خطا، دانلود و آپلود
- فیلتر نوع محتوا و مقصد جداگانه برای هر نوع (`routes`)
- پاک‌سازی متن: لینک تلگرام (از جمله لینک‌های مخفی)، یوزرنیم، هشتگ، لینک خارجی
- `drop_lines_containing`، `skip_if_contains` و `append_text`
- جلوگیری از انتشار تکراری، حتی با چند مقصد
- تلاش مجدد برای پست‌های ناموفق (بدون از دست رفتن پست)
- پیام‌های دارای پیش‌نمایش لینک به‌درستی به‌عنوان متن منتشر می‌شوند
- احترام به کانال‌های دارای Content Protection
- حالت آزمایشی (`dry_run`) و اعتبارسنجی config

## راه‌اندازی

### ۱. گرفتن API تلگرام
به https://my.telegram.org برو و `API ID` و `API HASH` را بگیر.

### ۲. ساخت نشست (یک بار، روی کامپیوتر خودت)

```bash
pip install -r requirements.txt
python scripts/create_session.py
```

رشته چاپ‌شده همان `TG_SESSION` است و **دسترسی کامل به حساب** می‌دهد.
بهتر است از یک **حساب جداگانه** (نه حساب اصلی) استفاده کنی.

### ۳. آپلود پروژه در GitHub

زیپ را باز کن و داخل پوشه پروژه:

```bash
git init -b main
git add -A
git commit -m "Initial commit"
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

(پوشه `.github` مخفی است؛ با آپلود از وب‌سایت ممکن است نیاید، پس از `git push` استفاده کن.)

### ۴. Secrets

مخزن → Settings → Secrets and variables → Actions → New repository secret:

- `TG_API_ID`
- `TG_API_HASH`
- `TG_SESSION`

### ۵. تنظیم کانال‌ها
فایل `config.yaml` را ویرایش کن: `peer` (منبع)، `destinations` (مقصد)، `enabled: true`.
حساب تلگرام باید عضو کانال منبع باشد و در مقصد اجازه ارسال داشته باشد.

بررسی صحت config (بدون اتصال به تلگرام):

```bash
python -m app.main --check
```

### ۶. اجرای آزمایشی
Actions → Telegram Auto Publisher → Run workflow (با `dry_run = true`).

- اولین اجرا فقط نقطه شروع را روی آخرین پست ثبت می‌کند و چیزی منتشر نمی‌کند.
- یک پست جدید در کانال منبع بگذار (حداقل یک دقیقه صبر کن) و دوباره اجرا کن.
- پیش‌نمایش در لاگ اجرا (`[DRY RUN]`) دیده می‌شود.
- در حالت `dry_run` پست‌ها «پردازش‌شده» حساب نمی‌شوند؛ با اجرای واقعی منتشر می‌شوند.

### ۷. انتشار واقعی
یا در `config.yaml` مقدار `dry_run: false` بگذار، یا هنگام Run workflow گزینه `false` را انتخاب کن.

## نکات مهم

**هزینه اجرا:** مخزن Public در GitHub Actions رایگان و نامحدود است. مخزن Private سهمیه ماهانه دارد (حدود ۲۰۰۰ دقیقه)؛ اجرای هر ۵ دقیقه ممکن است از آن بیشتر شود، پس در `publish.yml` عدد cron را بزرگ‌تر کن (مثلاً `*/15`). شاخه `state` فقط آیدی کانال‌ها و پست‌ها را نگه می‌دارد، نه محتوا.

**زمان‌بندی:** اجرای cron در GitHub تضمینی نیست و گاهی چند دقیقه تأخیر دارد.

**ریسک حساب:** استفاده از حساب شخصی از IP دیتاسنتر و ارسال زیاد می‌تواند باعث محدودیت یا بسته‌شدن نشست شود. از حساب جداگانه استفاده کن و `poll_limit` و تعداد کانال‌ها را کم نگه دار. اگر نشست باطل شد، لاگ پیام واضحی می‌دهد؛ دوباره `create_session.py` را اجرا کن و Secret را عوض کن.

**حقوق محتوا:** فقط محتوایی را بازنشر کن که مالکش هستی یا اجازه داری. کانال‌های دارای محدودیت ذخیره/فوروارد به‌صورت پیش‌فرض رد می‌شوند.

**محدودیت‌ها:** کپشن مدیا بیشتر از `caption_limit` به‌صورت پیام جدا فرستاده می‌شود. متن بیشتر از ۴۰۹۶ حرف بدون قالب‌بندی و در چند پیام فرستاده می‌شود. نظرسنجی، استیکر، موقعیت و مخاطب منتشر نمی‌شوند. ویرایش یا حذف پست منبع در مقصد اعمال نمی‌شود.

**وضعیت:** در شاخه `state` ذخیره می‌شود. این شاخه را حذف نکن (حذفش یعنی شروع دوباره از آخرین پست).

## قوانین پاک‌سازی (`text_rules`)

| کلید | کار |
|---|---|
| `remove_telegram_links` | حذف لینک t.me (متنی یا مخفی در متن) |
| `remove_usernames` / `remove_mentions` | حذف `@username` |
| `remove_hashtags` | حذف هشتگ |
| `remove_external_links` | حذف لینک بیرونی (لینک مخفی: متن می‌ماند، لینک حذف می‌شود) |
| `remove_caption` | حذف کپشن مدیا |
| `drop_lines_containing` | حذف خطوطی که این عبارت‌ها را دارند |
| `skip_if_contains` | منتشر نکردن پست‌هایی که این کلمات را دارند |
| `append_text` | متن ثابت انتهای پست (HTML مجاز) |
